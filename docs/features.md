# 功能路线

## 开发顺序

`smalux` 采用后台优先策略：

1. 后台管理能力。
2. 监控数据与实时更新。
3. 安全、审计和主题上传。
4. 部署适配。
5. 公开主页和主题生态。

## 重设计后的主模块

后台主模块调整为：

- 总览
- 服务器
- Ping 监测
- 远程执行
- 通知
- 账户
- 日志
- 主题
- 系统设置
- 部署

详细模块边界见 [模块设计](./modules.md)。

## P0 功能

P0 是第一版必须跑通的后台基础。

### 监控总览

内容：

- 节点总数。
- 在线、警告、离线数量。
- 平均 CPU。
- 平均内存。
- 总流量。
- 异常节点列表。
- 最近事件。

组件要求：

- 统计卡片可复用。
- 状态标签统一使用 `StatusBadge`。
- 资源条统一使用 `PercentBar`。
- 趋势图先用轻量组件占位，后续接 uPlot。

### 节点管理

后续 UI 名称调整为“服务器”，代码里的 `Node` 类型可在后续联调阶段再逐步改名，避免当前骨架一次性大范围重命名。

内容：

- 节点列表。
- 节点状态。
- 分组、地区、标签。
- CPU、内存、磁盘、网络、延迟。
- 节点详情。
- Agent Token 创建、复制、吊销。
- Agent 密钥轮换。

桌面端：

- 使用表格。
- 支持筛选、排序、分页。

移动端：

- 使用卡片列表。
- 避免横向滚动。
- 保留关键指标，不展示过多列。

### 指标图表

内容：

- CPU。
- 内存。
- 磁盘。
- 网络入站/出站。
- 负载。
- 延迟。
- 时间范围。

性能要求：

- 高频趋势图使用 uPlot。
- 图表数据进入图表前做降采样。
- 默认限制可视时间窗口。
- 节点卡片不订阅不需要的指标。

## P1 功能

P1 是正式可用后台需要具备的能力。

### 告警通知

内容：

- 告警规则。
- 阈值配置。
- 通知渠道。
- 静默窗口。
- 测试通知。
- 告警历史。
- 恢复事件。

安全要求：

- 测试通知属于写操作，需要 CSRF。
- Webhook token、SMTP 密码等敏感配置不能明文存储。

### 远程执行

远程执行拆成：

- 直接执行。
- 定时执行。
- 命令模板。
- 执行记录。
- 执行输出。

第一版只做后台模块和 API 边界，真实执行必须等后端权限、审计和 Agent 协议确定后再接入。

### Ping 监测

Ping 监测用于外部可用性检查。

第一版需要支持：

- HTTP 探测。
- TCP 探测。
- 延迟。
- 可用率。
- 告警联动。

ICMP 是否支持由后端部署权限决定。

### 账户与日志

账户模块：

- 用户。
- 角色。
- MFA。
- Passkey。
- 会话。

日志模块：

- 审计日志。
- 执行日志。
- 告警日志。
- 通知日志。
- 系统日志。

### 主题系统

后台主题：

- 浅色。
- 深色。
- 跟随系统。
- 自定义主色。
- 图表色。
- 圆角、密度、字体。

公开主页主题：

- 上传 zip。
- 预览。
- 启用。
- 回滚。
- 删除。

主题包建议结构：

```txt
theme.zip
  komari-theme.json
  dist/
    index.html
    assets/
  preview.png
```

### 安全审计

必须记录：

- 登录。
- 登出。
- 创建 Token。
- 吊销 Token。
- 节点删除。
- 告警规则修改。
- 主题上传。
- 主题启用。
- 危险设置修改。

## P2 功能

P2 是增强和交付能力。

### 部署适配

- 独立静态部署。
- Nginx 部署。
- Rust Web 内置。
- 运行时配置管理。
- 静态资源缓存策略。

### 公开主页

目标：

- 状态展示好看。
- 移动端可读。
- 可公开访问。
- 不携带后台 Cookie。
- 只调用公开 API。

可复用后台组件：

- `StatusBadge`
- `PercentBar`
- `MetricPill`
- 监控卡片
- 图表组件
- 主题 token

## 功能开发规则

- 新功能先定义领域类型。
- 再定义 API schema。
- 再写 model 转换。
- 最后写页面和组件。
- 每个功能至少保留一个测试点：纯函数、schema 或交互。
