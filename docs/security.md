# 安全设计

## 安全目标

`smalux` 是监控类系统，后台入口、Agent 通道、主题上传、数据备份和通知配置都属于高价值目标。安全设计目标是：

- 后台会话不暴露长期 token，支持多端会话识别与外部终端一键踢出。
- 管理员账户具备强密码策略与 TOTP 双因子动态口令防护，防未授权降级。
- 写操作防 CSRF 与参数越权。
- WebSocket 不被跨站滥用，实施严格消息签名。
- 主题上传与静态大盘沙箱隔离，不影响后台安全。
- 备份快照支持 AES-256 全文加密，异地冷备与本地存储严格隔离。
- Agent 上报防伪造、防重放。
- 敏感配置不明文存储，危险与敏感操作 100% 审计可追踪。

---

## 认证与多端会话管理 (Authentication & Sessions)

### 1. 会话机制
推荐方案：
- `HttpOnly` Cookie 与安全标志 (`Secure`, `SameSite=Lax/Strict`)。
- 短周期 Access Token + 自动 Refresh Rotation。
- **多端登录会话管理 (`/api/v1/security/sessions`)**：
  - 服务端记录每个终端会话的 Session ID、User-Agent、客户端 IP、地理位置与最后活跃时间；
  - 前端高亮显示 `[当前终端]`；
  - 支持**强制注销单个可疑终端**与**一键强制注销其他所有外部终端** (`POST /api/v1/security/sessions/terminate-others`)，有效化解 Session 劫持与异地残留风险。

Cookie 建议：
```txt
__Host-smalux_session
```

前端要求：
- 不把长期敏感 Token 存入 `localStorage`；
- 权限守卫在路由层和服务端双重校验。

### 2. TOTP 双因子认证 (2FA) 与防降级策略
- **标准 RFC 6238 TOTP**：动态生成 32 位 Base32 Secret 与标准 `otpauth://totp/...` 协议 URI，兼容主流 Authenticator（Google、Microsoft、1Password 等）；
- **二次验密防护**：
  - 更换 Authenticator 设备或关闭/解绑 TOTP 时，必须强制校验当前管理员登录密码；
  - 启用 TOTP 后，修改管理员密码必须强制提交 6 位动态口令。

### 3. 密码安全策略
- 支持客户端一键生成 16 位高强度随机密码；
- 实施长度、大小写、数字、特殊符号 4 维实时强度评分。

## 备份与数据安全 (Backup & Disaster Recovery Security)

### 1. 快照加密与解密还原
- **AES-256 加密归档**：快照归档支持在打包时使用对称密钥进行端到端加密；
- **高危覆盖还原安全**：
  - 触发快照覆盖还原前，系统强制弹出高危预警与解密密钥输入；
  - 还原前自动触发创建底层只读回滚快照点。

### 2. 异地冷备隔离 (S3 / WebDAV)
- **存储互斥隔离**：选择远程冷备时，备份文件直接推送到 Amazon S3 或 WebDAV 远程端点，本地不保留明文副本，避免敏感数据在本地持久化。

## CSRF 防护

适用范围：
- 创建/删除节点。
- 创建/吊销 Token。
- 修改告警规则与通知渠道。
- 上传/启用主题。
- 修改系统全局配置与备份策略。

设计：
- 写操作携带 CSRF token；
- 服务端严格校验 token、Origin、Referer；
- JSON-RPC 写 method 也必须走 CSRF 或等效机制。

---

## WebSocket 安全

用途：
- 实时监控遥测数据。
- 节点在线状态与心跳。
- 事件流水。
- 交互式终端或任务分发。

要求：
- 生产环境仅允许 WSS；
- 校验 Origin；
- 使用 Cookie 会话或一次性 WS ticket；
- 连接建立后做订阅级细粒度权限判断；
- 心跳和超时断开；
- 消息体使用 Zod Schema 运行时严格校验；
- 限制订阅数量和消息吞吐大小。

前端要求：
- WS 数据进入专用响应式 store；
- 批量更新与节流合并，避免高频单条消息导致整页重渲染。

---

## JSON-RPC 安全

适用：
- 刷新节点状态、测试通知渠道、批量操作、任务执行、高危命令分发。

要求：
- 每个 method 独立鉴权；
- 限制 batch 请求大小；
- 写 method 100% 记录审计流水；
- 高危 method 需要二次密码确认；
- 响应使用 Zod 运行时严格校验。

---

## 远程执行与命令安全

远程执行是高风险模块，不可单纯依赖前端按钮限制：
- 每次执行必须强制写审计日志；
- 直接执行需要二次确认；
- 高危命令（High Risk）强制流转审批；
- 定时执行需要记录创建人、修改人、启用人；
- 执行目标必须展示确切影响范围；
- 输出日志与终端回显自动脱敏；
- 超时时间、最大并发、重试次数必须严格设限；
- 禁止未授权角色查看敏感命令输出。

---

## 主题上传安全

风险：主题包可能包含 HTML、CSS、JS，本质上属于上传可执行前端代码。

服务端校验：
- 限制 zip 体积；
- 禁止路径穿越与绝对路径；
- 必须包含完整 manifest 与 `dist/index.html`；
- 限制允许的文件扩展名；
- 解压至独立沙箱目录；
- 支持随时一键回滚与删除。

隔离要求：
- 公开展示主题页面不携带后台敏感 Cookie；
- 公开展示页仅允许访问受限的公开只读 API；
- 后台控制台与公开大盘使用不同 CSP 策略。

---

## Agent 通道安全

注册：
- 注册 Token 一次性使用与时效控制（TTL 60~600秒）；
- 创建后仅展示一次，服务端仅持久化 Hash 密文。

上报：
- HMAC-SHA256 签名校验；
- 带 timestamp、nonce 防重放攻击窗口；
- 服务端校验客户端时钟偏差。

---

## 敏感配置与密钥管理

敏感项：
- Webhook 机器人 Token、SMTP 密码、Agent Secret、S3 AccessKey/SecretKey、WebDAV 密码。

存储规范：
- 密码哈希使用 Argon2id；
- 可逆敏感配置使用 AEAD 加密；
- 密文记录 Key Version，主密钥来自环境变量或 KMS。

---

## 审计日志 (Audit Trail)

系统 100% 记录以下安全审计事件：
- 登录、登出、外部会话强制下线；
- MFA 开启、关闭与设备更换；
- API Token 签发与吊销；
- 自动备份计划创建、修改、启停与立即执行；
- 数据快照生成、恢复与按需清理；
- 告警规则与通知渠道修改；
- 主机节点删除与系统设置更新。
